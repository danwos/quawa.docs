Scoring¶

Levels build on each other¶

Every level adds measures to those below (Levels build on each other:... (DEC_INCREMENTAL_LEVELS)). A stricter threshold on a higher level is a new measure there – coverage ≥ 30 % on level 2, ≥ 60 % on level 3 and ≥ 80 % on level 4 are three measures fed by the same check.

From check to area¶

  • Check score 0–100: binary checks give 0 or 100. Numeric checks give 100 when the threshold is met, below that linear towards 0 (value / threshold for “higher is better”, threshold / value for “lower is better”, e.g. findings). Existence checks are binary.

  • Measure score = mean of its checks.

  • Area score on a level = mean of the measures this level adds. A measure without a result (not defined, no result, broken) counts 0. Only when none of them has a result the segment shows a grey or hatched state instead – broken before defined before not defined.

  • Weights per measure are possible later; the first version uses the plain mean.

Reached¶

  • A level is reached in an area when it and every level below score 100.

  • The reached level of an area is the highest such level. A level above a hole can pass on its own (mutation tests on level 4 run while level 2 fails); it is shown, but not reached.

  • Areas are independent of each other; inside an area it is a strict ladder (Inside an area the levels a... (DEC_STRICT_LADDER)).

  • Project level per area = lowest level of its modules (weakest link); overall project level = lowest area level (One scale for all areas; th... (DEC_WEAKEST_LINK)).

Existence checks are the honest start; AI-rated and review checks deepen the same measure later.
